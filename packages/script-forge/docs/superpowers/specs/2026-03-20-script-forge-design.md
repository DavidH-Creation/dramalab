# Script-Forge Design Spec

**Date**: 2026-03-20
**Status**: Draft → Reviewed
**Author**: David + Claude

## Conventions

- **Encoding**: All file I/O MUST specify `encoding="utf-8"` explicitly. This is critical on Windows where the default locale is often GBK/cp936, which will corrupt Chinese text.
- **Atomic writes**: All writes to `.script-forge/state.json` must use write-to-temp + `os.replace` pattern to prevent corruption on crash or concurrent access.
- **File lookups**: Sequence files are discovered via `manifest.json`, never by filename convention. This allows user-defined naming.

## 1. Project Overview

### What

Script-Forge is a CLI tool that automatically and iteratively improves screenplays. Inspired by [karpathy/autoresearch](https://github.com/karpathy/autoresearch), it applies the "modify → evaluate → keep/discard → repeat" loop to screenplay text instead of ML training code.

### Core Loop

```
1. Identify weakest scoring dimension
2. Generate a candidate modification (scoped to 1-3 scenes)
3. Score the candidate (3× independent evaluations, take median)
4. If improved: commit candidate as new baseline
5. If not improved: discard candidate, revert to baseline
6. Log result, continue
```

### Backend

Claude Code CLI (`claude -p`). Uses the user's existing subscription. No API key required.

### Install & Use

```bash
pip install script-forge

script-forge init screenplay.docx --criteria scoring.docx
script-forge run --mode micro --rounds 20
script-forge status
script-forge export --output improved.docx
```

## 2. Architecture

### 2.1 Two-Layer Separation: Package vs Workspace

The **installed package** (`script-forge`) contains source code, templates, and tests. It never stores project data.

The **workspace** is a user-facing directory generated by `script-forge init`. All mutable state lives here. The workspace is a git repo.

```
# Installed package (source repo / PyPI)
script-forge/
├── src/script_forge/       # Python source
├── templates/              # Example criteria, prompt templates
├── tests/                  # Unit + integration tests
├── pyproject.toml
├── README.md
└── LICENSE

# Generated workspace (per-project, created by `init`)
my-screenplay-project/
├── input/
│   ├── screenplay.docx         # Original input (read-only archive)
│   └── criteria.docx           # Original criteria (read-only archive)
├── sequences/                  # ★ Single source of truth
│   ├── manifest.json           # Segment metadata (order, char counts, markers)
│   ├── seq_001_ep01-06.md
│   ├── seq_002_ep07-14.md
│   └── ...
├── derived/                    # Auto-generated, never manually edited
│   ├── synopsis.md
│   └── context.md
├── experiments/                # Per-experiment logs
│   └── exp_001.json
├── exports/                    # Output files
├── .script-forge/
│   ├── project.toml            # Project config (model, thresholds, criteria path)
│   ├── state.json              # Machine-readable state for resume
│   └── history.jsonl           # Append-only experiment log
├── results.tsv                 # Human-readable summary
└── .gitignore
```

### 2.2 Single Source of Truth

`sequences/*.md` is the **only editable truth**. Everything else is derived.

| File | Role | Mutability |
|------|------|-----------|
| `sequences/*.md` | Screenplay text segments | **Editable** (by modifier only) |
| `sequences/manifest.json` | Segment metadata | **Editable** (by splitter/reorder) |
| `derived/synopsis.md` | Full-story outline | **Derived** — regenerated after every keep |
| `derived/context.md` | Character table, connections, transitions | **Derived** — regenerated after every keep |
| `input/*.docx` | Original files | **Read-only** archive |
| `.script-forge/state.json` | Loop state | **Machine-managed** |

**Derivation rule**: After every successful `keep`, the system calls `derive()` which regenerates `synopsis.md` and `context.md` from the current sequences via Claude CLI.

### 2.3 Macro vs Micro Mode

Both modes edit `sequences/*.md`. The difference is **scope and evaluation granularity**.

**Micro mode**:
- Operates on one sequence at a time
- Scores that sequence only (6 dimensions, /60)
- Modifications scoped to 1-3 scenes within the sequence
- Moves to next sequence after 5 consecutive stalls

**Macro mode**:
- First regenerates `derived/synopsis.md` from all sequences
- Scores the synopsis (all 10 dimensions, /100)
- Identifies the weakest structural dimension
- Locates which sequence(s) to modify
- Applies structural changes to the relevant sequence file(s)
- After commit, regenerates derived files

**Auto mode** (recommended):
```
macro × 3 rounds → micro all sequences → macro × 1 round (validation)
```

### 3.3 backends/ — LLM Adapter Layer

```python
# backends/__init__.py
class BackendProtocol(Protocol):
    def query(self, prompt: str, *, timeout: int = 300) -> str:
        """Send prompt, return response text."""
        ...

    def query_json(self, prompt: str, *, timeout: int = 300, retries: int = 2) -> dict:
        """Send prompt, parse JSON from response. Retry on parse failure."""
        ...
```

```python
# backends/claude_cli.py
class ClaudeCLIBackend:
    def __init__(self, model: str = "sonnet", timeout: int = 300):
        self.model = model
        self.timeout = timeout

    def query(self, prompt: str, *, timeout: int | None = None) -> str:
        t = timeout or self.timeout
        result = subprocess.run(
            ["claude", "-p", prompt, "--model", self.model, "--no-input"],
            capture_output=True, text=True, encoding="utf-8",
            timeout=t
        )
        if result.returncode != 0:
            raise BackendError(f"Claude CLI failed: {result.stderr[:500]}")
        return result.stdout

    def query_json(self, prompt: str, *, timeout: int | None = None, retries: int = 2) -> dict:
        current_prompt = prompt
        for attempt in range(retries + 1):
            raw = self.query(current_prompt, timeout=timeout)
            try:
                return extract_json(raw)
            except JSONParseError:
                if attempt == retries:
                    raise
                # On retry, append stronger JSON-forcing suffix
                current_prompt = prompt + (
                    "\n\n[IMPORTANT: Your previous response was not valid JSON. "
                    "Output ONLY a valid JSON object. No markdown, no explanation, "
                    "no code fences. Start with { and end with }.]"
                )
```

```python
# backends/mock.py
class MockBackend:
    """Deterministic backend for testing. Returns pre-configured responses."""
    def __init__(self, responses: list[str]):
        self.responses = responses
        self.call_count = 0
        self.prompts: list[str] = []  # Record prompts for assertion

    def query(self, prompt: str, **kwargs) -> str:
        self.prompts.append(prompt)
        resp = self.responses[self.call_count % len(self.responses)]
        self.call_count += 1
        return resp
```

### 3.4 splitter.py

```python
def split_screenplay(docx_path: Path, backend: BackendProtocol) -> list[SequenceInfo]:
    """
    Auto-segment a screenplay docx into sequences.

    Strategy:
    1. Extract paragraphs via python-docx
    2. Identify structural markers via regex:
       - Chinese: 场\d+-\d+, 第.{1,4}集, 第.{1,3}幕
       - English: INT\./EXT\., ACT\s+\w+, SCENE\s+\d+
    3. Group scenes into episodes (by episode markers)
    4. Merge episodes into sequences targeting 8K-15K chars each
    5. If no markers found → call backend to identify structure
    6. Write sequences/*.md files + manifest.json
    """
```

**Merge heuristic**: Greedily merge consecutive episodes until adding the next would exceed 15K chars. Never split mid-episode.

**Fallback**: If regex finds < 3 markers, send first 3000 chars to backend with prompt: "Identify the structural markers in this screenplay (scene breaks, episode breaks, act breaks). Return as JSON list."

### 3.7 git_ops.py — Candidate-Based Git Safety

**No `git reset --hard`.** Instead use a candidate file approach:

```python
def apply_candidate(workspace: Path, sequence_id: str, new_text: str) -> Path:
    """Write candidate to sequences/{id}.md. Returns the file path.
    Looks up actual filename from manifest.json."""
    manifest = load_manifest(workspace)
    filename = manifest[sequence_id].filename
    path = workspace / "sequences" / filename
    # Save backup to .script-forge/backup_{sequence_id}.md
    backup = workspace / ".script-forge" / f"backup_{sequence_id}.md"
    shutil.copy2(path, backup)
    path.write_text(new_text, encoding="utf-8")
    return path

def commit_keep(workspace: Path, sequence_id: str, message: str) -> str:
    """Commit the candidate. Remove backup. Return short hash."""
    manifest = load_manifest(workspace)
    filename = manifest[sequence_id].filename
    backup = workspace / ".script-forge" / f"backup_{sequence_id}.md"
    subprocess.run(["git", "add", f"sequences/{filename}"], cwd=workspace)
    subprocess.run(["git", "commit", "-m", message], cwd=workspace)
    backup.unlink(missing_ok=True)
    return get_short_hash(workspace)

def discard_candidate(workspace: Path, sequence_id: str):
    """Restore from backup. No destructive git commands."""
    backup = workspace / ".script-forge" / f"backup_{sequence_id}.md"
    manifest = load_manifest(workspace)
    filename = manifest[sequence_id].filename
    target = workspace / "sequences" / filename
    shutil.copy2(backup, target)
    # Verify restoration matches git HEAD (belt-and-suspenders)
    result = subprocess.run(
        ["git", "diff", "--stat", f"sequences/{filename}"],
        capture_output=True, text=True, cwd=workspace
    )
    if result.stdout.strip():
        logger.warning(f"File {filename} still differs from HEAD after restore")
    backup.unlink(missing_ok=True)
```

This approach:
- Only touches the file being experimented on
- Never affects unrelated files in the workspace
- No destructive git commands (`reset --hard`, `checkout --`) at all
- Backup file provides an extra safety net
- Verification step catches any restore anomalies

### 3.8 state.py — State Persistence

Three layers:

| File | Format | Purpose | Reader |
|------|--------|---------|--------|
| `results.tsv` | TSV | Human-readable summary | Human |
| `.script-forge/history.jsonl` | JSONL | Append-only experiment log | Machine + Human |
| `.script-forge/state.json` | JSON | Current loop state for resume | Machine |

**Concurrency safety**:
- `state.json`: Written via atomic `os.replace` (write to `.state.json.tmp`, then replace).
- `history.jsonl`: Append-only, safe for concurrent reads. Writers use file-level lock (`.script-forge/.lock`).
- `run` command acquires `.script-forge/.lock` on startup. If lock exists and process is alive, exit with error. Stale locks (process dead) are cleaned up automatically.
- `status` and `score` commands are read-only and never acquire the lock.

**state.json** enables `script-forge run` to resume from where it left off after interruption:

```json
{
  "version": 1,
  "current_mode": "micro",
  "current_sequence": "seq_001",
  "round_number": 14,
  "stall_count": 2,
  "total_keeps": 8,
  "total_discards": 6,
  "baseline_scores": {
    "seq_001": {"total": 38, "max": 60, "scores": {"情节设置": 7, ...}},
    "global": {"total": 62, "max": 100, "scores": {...}}
  },
  "last_experiment_id": 14,
  "backend": "claude_cli",
  "model": "sonnet"
}
```

**Resume logic**: On startup, `loop.py` checks for `state.json`. If present and `--resume` (default), it continues from the saved state. If `--fresh`, it re-baselines.

### 3.9 loop.py — Main Controller

```python
def run_loop(
    workspace: Path,
    mode: Literal["macro", "micro", "auto"],
    rounds: int | None,       # None = until-stalled
    backend: BackendProtocol,
):
    state = load_or_init_state(workspace, mode)
    criteria = load_criteria(workspace)
    stall_limit = 5

    while not should_stop(state, rounds, stall_limit):
        if state.current_mode == "macro":
            run_macro_round(workspace, state, criteria, backend)
        else:
            run_micro_round(workspace, state, criteria, backend)

        # Auto mode phase transitions
        if state.auto_phase == "macro_initial" and state.macro_rounds_done >= 3:
            transition_to_micro_sweep(state, workspace)
        elif state.auto_phase == "micro_sweep" and all_sequences_stalled(state, workspace):
            transition_to_macro_validation(state)
        elif state.auto_phase == "macro_validation" and state.macro_rounds_done >= 1:
            state.auto_phase = "done"  # Will trigger should_stop

        save_state(workspace, state)  # Atomic write via os.replace
        print_round_summary(state)

    print_final_summary(workspace)

# Auto mode phase transitions:
# 1. macro_initial: Run macro for 3 rounds
# 2. micro_sweep: Run micro on each sequence until stalled (5 consecutive non-improvements)
#    Move to next sequence when current stalls. Phase ends when all sequences have stalled.
# 3. macro_validation: Run macro for 1 round as final check
# 4. done: Exit
```

### 3.10 deriver.py

```python
def derive_all(workspace: Path, backend: BackendProtocol):
    """Regenerate synopsis.md and context.md from sequences."""
    sequences = load_all_sequences(workspace)  # respects manifest.json order
    full_text_summary = proportional_truncate(sequences, max_chars=30000)

    synopsis = backend.query(
        load_prompt("derive_synopsis", text=full_text_summary)
    )
    context = backend.query(
        load_prompt("derive_context", text=full_text_summary)
    )

    atomic_write(workspace / "derived" / "synopsis.md", synopsis)
    atomic_write(workspace / "derived" / "context.md", context)


def proportional_truncate(sequences: list[tuple[str, str]], max_chars: int) -> str:
    """Truncate sequences proportionally to fit within max_chars.

    Strategy: allocate chars to each sequence proportional to its length.
    For each sequence, take the first N chars (preserving paragraph boundaries).
    This ensures every sequence is represented in the summary, not just the first few.

    Example: 7 sequences totaling 70K chars, max 30K →
    each sequence gets ~4300 chars (proportional to its share of total).
    """
```

## 4. CLI Commands

```
script-forge init <screenplay.docx> [--criteria <criteria.docx>] [--output <dir>]
    Initialize a new workspace. Splits screenplay, generates derived files,
    runs baseline scoring, initializes git.

script-forge run [--mode macro|micro|auto] [--rounds N] [--sequence SEQ_ID] [--resume|--fresh]
    Run the optimization loop.
    Default: --mode auto --resume
    Default --rounds: until-stalled (stop when all sequences stall, 5 consecutive non-improvements each)
    Use --rounds -1 for truly infinite (must be explicit, prints warning).
    Use --rounds N for a fixed number of rounds.

    Acquires .script-forge/.lock — only one `run` process per workspace.

script-forge status
    Print results.tsv as a rich table + current state summary.

script-forge score [--sequence SEQ_ID]
    Run a one-shot scoring (3× median). Useful for debugging prompts.
    Read-only: does NOT update state.json baselines. Results printed to stdout only.

script-forge export [--output <path.docx>]
    Merge all sequences back into a single docx.
    Text-level round-trip only — does not preserve original docx styling.

script-forge derive
    Manually regenerate derived/synopsis.md and derived/context.md.
```

## 7. Error Handling

| Scenario | Behavior |
|----------|----------|
| Claude CLI not found | `init`/`run` fail with clear error: "Claude Code CLI not found. Install from https://claude.ai/download" |
| Claude CLI timeout | Retry once. If second timeout, log as `error` in history, skip this round. |
| JSON parse failure | Retry up to 2 times with explicit "output ONLY valid JSON" appended. After 3 failures, log as `error`, skip. |
| Git not found | `init` fails with clear error. |
| Workspace state.json corrupt | Warn user, offer `--fresh` to re-baseline. |
| Keyboard interrupt (Ctrl+C) | Graceful shutdown: discard any in-progress candidate, save state, print summary. |
| Sequence file missing | Skip sequence, log warning, continue with next. |

## 8. Scope Boundaries (v1)

### In scope
- Docx input (Chinese and English screenplays)
- Claude CLI backend
- Micro, macro, auto modes
- Git-based version tracking within workspace
- Text-level docx export
- Resume from interruption

### Out of scope (future)
- API backend (Anthropic API direct)
- Multi-model adversarial scoring (e.g., Claude scores, GPT verifies)
- Web UI / dashboard
- Preserving original docx formatting in export
- Parallel scoring (concurrent CLI calls)
- Custom prompt injection points for users
- Non-screenplay text optimization (novels, articles)
