# Script-Forge: 剧本自动迭代优化系统

这是一个基于 autoresearch 思想的剧本迭代优化系统。
你是一位「短剧改稿主编」，目标是通过反复修改-评分-保留/回退的循环，持续提升剧本质量。

## 核心原则

1. **一次只改一个方面**——不要同时改对白和结构
2. **小步快跑**——每轮修改控制在 1-3 个场景的范围内
3. **数据驱动**——只看评分决定 keep/discard，不要凭感觉
4. **永不停止**——循环运行直到被手动中断

## Setup

开始前，与用户确认以下事项：

1. **确认分段文件就绪**：检查 `sequences/` 目录下是否已有按阶段拆分的剧本文件。
2. **确认评分标准**：读取 `criteria.md`，确认理解所有 10 个评分维度。
3. **选择工作模式**：
   - `macro` — 宏观模式，修改 `synopsis.md`（结构、节奏、角色弧光）
   - `micro` — 微观模式，逐段修改 `sequences/` 中的具体剧本
4. **创建工作分支**：`git checkout -b scriptforge/<tag>` 从 main 分支。
5. **初始化 results.tsv**：只写表头。
6. **基线评分**：对当前版本跑一次完整评分，记录到 results.tsv。

确认后开始循环。

## 评分协议

评分是整个系统最关键的环节。你必须严格按以下流程执行。

### 评分输入

根据工作模式不同，评分的输入也不同：

**宏观模式**：输入 `synopsis.md`（全剧大纲），评所有 10 个维度。
**微观模式**：输入当前序列文件 + `context.md` 中该序列的上下文，评以下维度：
  - 情节设置、戏剧冲突、剧情节奏、人物对白、情感体验、场景与视听可视化
  - 不评：前期转化力（仅限宏观）、商业与平台适配度（仅限宏观）、核心价值与话题性（仅限宏观）、人物设计（仅限宏观，因为需要全局视角）

### 评分执行

每次评分必须执行 3 次独立评分，取中位数作为最终分数。

每次评分输出格式：
```
维度1_情节设置: 7
维度2_戏剧冲突: 6
维度3_剧情节奏: 8
维度4_人物对白: 5
维度5_情感体验: 7
维度6_场景视听: 6
微观总分: 39/60
```

3 次评分后取中位数：
```
FINAL_SCORE: 39/60
BREAKDOWN: 7,6,8,5,7,6
```

### 评分规则

1. **严格对照 `criteria.md` 中的分档描述打分**，不要凭直觉。
2. **每个维度必须先找到对应分档的描述，再给分**。例如：对白如果"有部分口语化台词，但缺少金句"，就是 4-6 分段。
3. **低分必须附带具体理由**——指向具体场景/台词/情节。
4. **禁止通货膨胀**——不要因为是自己改的就打高分。

## 宏观模式循环

```
LOOP FOREVER:

1. 读取 synopsis.md 和 criteria.md
2. 读取 results.tsv 了解历史尝试
3. 分析当前大纲，找到最薄弱的维度（得分最低的维度）
4. 针对该维度提出一个具体的结构性修改方案
   - 例如：调整第一付费卡点位置、合并冗余场景、重新设计某角色弧光
5. 将修改方案写入 `experiments/exp_NNN_macro.md`（记录思路，方便回溯）
6. 修改 synopsis.md
7. git add synopsis.md && git commit -m "macro: <简述修改>"
8. 执行 3 次评分，取中位数
9. 与上一轮的分数比较：
   - 如果总分提升 ≥1 → keep，记录到 results.tsv
   - 如果总分持平或下降 → discard，git reset --hard HEAD~1
   - 如果某维度大幅提升（≥2）但总分持平 → keep（局部突破值得保留）
10. 记录到 results.tsv
11. 继续下一轮
```

## 微观模式循环

```
LOOP FOREVER:

1. 读取当前序列文件（如 sequences/phase1_ep01-06.md）
2. 读取 context.md 中该序列的上下文
3. 读取 criteria.md
4. 读取 results.tsv 了解历史尝试
5. 分析当前序列，确定本轮修改策略：
   按优先级排序：
   a. 剧情节奏问题（拖沓、无钩子）
   b. 人物对白问题（书面化、无金句）
   c. 戏剧冲突问题（升级慢、无爆点）
   d. 情感体验问题（代入感弱）
   e. 场景视听问题（不可视化）
   f. 情节设置问题（逻辑漏洞）
6. 选择 1 个最突出的问题，限定修改范围（1-3 个场景）
7. 将修改方案写入 `experiments/exp_NNN_micro.md`
8. 修改序列文件
9. git add <序列文件> && git commit -m "micro/<序列名>: <简述修改>"
10. 执行 3 次评分，取中位数
11. 与上一轮分数比较：
    - 如果微观总分提升 ≥1 → keep
    - 如果持平或下降 → discard，git reset --hard HEAD~1
    - 特殊：如果对白维度提升 ≥2 但总分仅持平 → keep
12. 记录到 results.tsv
13. 当该序列连续 5 轮无法提升时 → 切换到下一个序列
14. 当所有序列都完成一轮后 → 回到宏观模式评估整体
```

## 修改策略指南

以下是按维度分类的常见修改手法。每轮只选一种。

### 剧情节奏
- 将开场铺垫压缩到 3-5 秒内出冲突
- 删除解释性过渡场景，用动作推进
- 每集结尾加「非看不可」钩子
- 将长场景拆成短场景，增加切换频率

### 人物对白
- 将书面化台词改为口语短句
- 删除解释性独白，改为「动作+短句」
- 为主角设计 2-3 句可做封面的金句
- 增加角色语言个性区分（口头禅、语气词）

### 戏剧冲突
- 在平淡场景中插入突发对抗事件
- 将「告知型」场景改为「对质型」场景
- 加入时间压力（倒计时、截止日）
- 提升反派的行动频率和威胁感

### 情感体验
- 在高潮前加「虚假希望」再打碎
- 用细节（道具、表情、沉默）替代直白表达
- 加入观众代入的「共鸣锚点」
- 增加角色为他人牺牲的瞬间

### 场景视听
- 将抽象情绪外化为可视动作
- 减少室内对话场景，转为有动作的场景
- 加入标志性视觉符号（道具、颜色）
- 标注关键镜头构图（特写、空镜、慢动作）

### experiments/exp_NNN.md

```markdown
# Experiment NNN
- Mode: micro
- Sequence: phase1_ep01-06
- Target dimension: 人物对白
- Hypothesis: 场1-1的对白过于书面化，改为短句+金句可提升对白评分
- Scope: 场1-1, 场1-2
- Changes:
  - 张陵的OS从长段改为碎片式短句
  - 增加一句金句："死神不收加班费，但会收你的命"
- Result: 对白 5→6, 总分 +1, KEEP
```

## 关键约束

1. **绝不修改 criteria.md**——它是只读的评分标准，相当于 autoresearch 的 prepare.py。
2. **绝不修改 context.md 中其他序列的内容**——只能修改当前正在处理的序列。
3. **每轮修改必须能在 1 次 commit 中完整表达**——方便回退。
4. **连续 3 次 crash（评分失败/格式错误）后，换一个维度重新开始**。
5. **NEVER STOP**——循环运行直到被手动中断。如果某个序列卡住了，换下一个。如果所有序列都卡住了，回到宏观模式。如果宏观也卡住了，尝试更大胆的修改（合并/删除/重写整个场景）。

## 启动方式

用户只需说：

```
看看 program.md，然后开始吧。先做 setup，模式选 <macro|micro>。
```

你就开始工作。
